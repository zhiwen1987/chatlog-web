# 安全与密钥保管交接

**交接保管责任，不在文档、Git、Agent消息或普通工单中复制私钥。** 受限秘密引用必须在授权保管系统中转移，记录双方和验证结果；模板里的字段不是授予DSH读秘密的授权。

| 材料 | 持有方 | 文档可记 | 禁止 |
|---|---|---|---|
| 发证签名key | 进源网络KMS/HSM/隔离签名器 | key ID、用途、信任版本、审批/轮换/恢复人 | 私钥下发客户、随仓库打包、让模型签任意claims |
| 软件更新签名key | 发布团队受限CI | 公钥指纹、通道、恢复和撤回政策 | 与license key复用、关闭验签 |
| Windows/macOS发行证书 | 发行账号/CI受限保管 | 证书主体、期限、目标平台 | 私钥截图或加入.env.example |
| 部署/设备PoP key | 对应安装本地安全存储 | 公钥摘要、绑定/轮换记录 | 分享整个实例私钥用于“多设备方便” |
| 数据加密key | 客户自己的保管体系 | key version、恢复托管和权限流程 | 商业到期销毁/锁定客户key |
| PG/对象/备份凭证 | 分离的客户服务账号 | credential引用、scope、轮换日 | 一个账号删除主数据和全部备份 |
| OAuth/AI凭证 | 相应身份/提供商保管 | client/provider引用、audience、预算 | 把开发DSH key打包进产品 |

## 必需演练

丢失管理员登录但保有恢复材料；一个设备凭证撤销；授权中心短时不可达；旧签名key轮换；备份恢复后key可用；撤销/删除账本不倒退。每次演练用隔离环境，检查角色分离和审计。

## 交接后

撤销短期协助账号、过期配对码和不再需要的CI凭证；核对应急联系信息，更新访问清单。发现泄漏先限制新访问、保留脱敏证据、按受审查策略轮换；不能用自毁数据解决授权风险。

客户域与发行方域的交接包分开权限分发；不能把包含全部被授权客户名单的issuer审计资料发给任一客户。
