# 工程维护交接

交接人和接手人分别确认，不由同一个代理替双方签字。本表描述所需资料；当前软件状态在项目根交接总览中为unknown/not_tested。

| 类别 | 必交内容 | 接手者核验动作 |
|---|---|---|
| 源码 | repo、分支/commit、dirty归属、submodule、生成器与锁文件 | 安全读取状态，核对hash，不reset清现场 |
| 规则 | AGENTS/规则/手册版本摘要，ADR与已批准偏离 | 检查无多份冲突指令，旧版只追溯 |
| 构建 | 每平台实际命令、工具版本、CI入口、产物位置 | 在独立环境复现，不拿旧日志顶替 |
| 数据 | DB/local-state/claims/sync版本、迁移owner、索引及水位 | 核对现有状态，不重复迁移/重编号 |
| 业务 | 已实现和未实现矩阵、实际OpenAPI/ToolRegistry | 查handler和测试，不把菜单当成功 |
| 运行 | namespace、卷/对象前缀、端口、镜像digest、配置引用 | 最小权限观察，不能直接改生产 |
| 当前工作 | P阶段、每项status、A/B/C run ID/owner/generation | 查旧进程/外部job再决定接管 |
| 测试 | 命令、源码摘要、环境、退出码、日志/报告hash | 关键反例重做，过期证据不沿用 |
| 风险 | 已知缺陷、blocked、临时兼容、到期证书与容量限制 | 按风险排序指定owner和恢复条件 |
| 交付 | 安装、升级、恢复、MCP、授权和用户说明 | 以真实发行清单抽检一轮闭环 |

## 接手演练

选择一次未成功同步/心跳误判或授权批次失败的合成案例，接手者从错误码沿request→operation→job/attempt找到原因，修复一个最小项，在当前快照跑回归并更新手册。不得靠查看原代理内部思考解释设计。

## 恢复开发的第一小时内应明确的事实

当前workspace、活动任务、合同版、下一可执行项、允许修改路径、真实测试入口、已发生且不能重复的副作用。没有资源不强制承诺时间，只按事实完成清单。

本包不自动迁移`.delivery/`；使用[模板](../../templates/HANDOFF.md)建立新交接记录并保留旧记录版本。交接资料中的日志先脱敏，再授予接手人最小读权限。
