# 架构与数据流 · 接手者导航

此图描述目标架构，不是已经部署的拓扑。模块和数据定义以规则R04～R12/R14～R16/R33/R42为准。

```text
DSH开发区：协调者 + A/B/C执行槽 → 代码/合同/测试/文档（不连接生产秘密）

员工桌面                 客户自己的服务端                        发行方
原生SourceAdapter       HTTPS网关 / REST / MCP                  独立授权中心
  →加密Outbox ───────→  AuthContext + Policy + Entitlement      管理员/审批者
  →媒体流式上传         + Approval + ResourceBudget               →签名服务
  ←耐久receipt          Application Services                      →签名授权
  ↔presence心跳           ├─PostgreSQL事实/事务outbox/jobs            ↓
                         ├─ObjectStore原件/分片/派生件            客户验签缓存
Web/受信AI Host ─────→    ├─QueryService → PG/搜索投影           （不传聊天）
                         └─受限Worker → 索引/媒体/画像/备份
```

## 三个进度与两个授权域最容易混淆

传输receipt是服务端已经耐久接受的事实；publish/index是业务可读与索引覆盖；media_verified/backed_up分别是原件校验与灾备。它们可以不同步更新。presence在线完全不代替其中任何一个。

对应已冻结 schema（禁止在 app 目录重复定义）：
- 采集收据 `packages/protocol/media-receipt.json`：仅在耐久提交后发出；object_ref/media_kind 成对，backup_set 用于恢复对账；PG 损坏/丢失时不发假 ACK。
- 媒体对象清单 `packages/protocol/media-manifest.json`：object_ref 复合分区唯一、sha256 不覆盖、bytes_ref 引用对象存储、state=quarantined 毒数据隔离。
- 完整性报告 `packages/contracts/integrity-report.json`：counts 需一致（verified+pending+excluded+source_missing ≤ in_scope ≤ total_discovered），状态含 excluded_by_license/source_missing 等，不冒充完整。

客户Policy决定数据权限；发行方Entitlement说明商业权利。企业desired_enabled是本地运行选择；不能伪造signed grant。客户MCP不能执行发行方批量授权，issuer管理员也不因此能读取客户消息。商业许可 claims v2 的 feature_grants[] 是商业权利唯一来源（`packages/contracts/license-claims.json`），feature_catalog_version 与 feature-catalog.json 对齐、license_revision 标识版本；未签名不能作激活码。

## 改代码时沿哪条链找

| 问题 | 首先定位的边界 | 不该直接修改 |
|---|---|---|
| 重复/漏消息 | SourceAdapter→identity→Outbox→ingest receipt→publish | 不能改UI计数或跳checkpoint遮盖 |
| 文件上传后不可播 | 原件校验→MIME/安全扫描→派生job→播放器 | 不覆盖原文件，不把转码失败改为verified |
| 搜索漏旧数据 | QueryService→分区目录→索引水位→严格补差 | 不从索引命中数推全库数量 |
| 在线误判 | presence service→设备session/seq→权威接收时钟 | 不用客户端墙上时间延长lease |
| 授权已发未生效 | issuer published→客户renew→验签→effective snapshot | 不改前端布尔值或让客户自签 |
| 任务重复执行 | 幂等key→job lease/fencing→最终发布事务 | 不仅启动时检查fencing |
| 清洗破坏历史 | raw observation→projection generation→manual overlay→rollback | 不直接UPDATE原文“修正” |

## 存储分层

PG保存结构事实、身份、权限、作业和索引定位；对象存储保存原件及受控派生文件；搜索/向量/画像是可重建派生；客户端SQLite保留本地队列和checkpoint。不可用向量库或缓存作为唯一数据源。

TB数据按R03分附件容量和可检索正文，保留六项计量及放大预算。R07规范分区/键，R11规范精确查询，R29规范负载下延迟。新增技术组件必须证明瓶颈，不一开始为每个功能增加微服务。

## 接口与二次开发

代码里每个模块有一个写owner。协议Handler不写SQL，Repository不决定许可，Domain不导入Web/Tauri/MCP SDK。新来源实现SourceAdapter，新对象后端实现ObjectStore，新工具调现有ApplicationService；边界和失败合同一起测试。
