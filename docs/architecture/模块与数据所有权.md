# 模块与数据所有权导航

本文件是规则R07/R39/R42的数据字典入口，不复制DDL或创造另一个迁移序列。实际表、列类型、唯一键、FK、索引、RLS、保留与迁移均由`packages/contracts/`和受审查SQL实现，交接时补实际路径与commit。

| Owner | 负责写入的事实 | 输入/输出边界 | 故障时的保留规则 |
|---|---|---|---|
| Identity/Policy | 用户、租户成员、对象授权、策略epoch | AuthContext→决策 | 默认拒绝；不自动借管理员身份 |
| Device/Presence | enrollment、device session、seq和lastSeen | 有界心跳→receipt | 旧seq不刷新在线；观察不可用=unknown |
| Source/Sync | 来源/分片generation、记录身份、观察、receipt和水位 | 原始来源→标准化事件 | 来源只读；毒数据隔离，不假ACK；来源游标 cursor.watermark 是单调 seq 十进制字符串，按回放推进（`packages/source-contract/source-adapter.json`） |
| Chat/Query | 消息元数据、body/revision、分区定位 | 查询合同与覆盖 | 稳定消息不因修订换身份；unknown不填假值 |
| Media | object/ref/session/parts/derivatives | bytes流、hash、引用 | 部分上传可续；原件不可被转码覆盖 |
| Customer/Profile | identity关联、备注/标签、facts/evidence/snapshots | 关联及证据→业务视图 | 不改原聊天；人工新版本不被AI覆盖；画像 derived.unique_source 必须为 false，画像是可重建派生非唯一数据源（`packages/profile-schema/profile-schema.json`） |
| Jobs/Projection | job/attempt/event、发布任务与索引水位 | 事务outbox→有界worker | fencing控制最终提交；无进度独立看护 |
| Quality/Retention | issue、清洗plan/run、projection版本、删除抑制 | preview→approval→apply/rollback | 原文保留；恢复先应用删除账本 |
| Customer Entitlement | 已验签snapshot、local desired、用量预留/账本 | 发行方签名→本地有效能力 | 到期保取回；换grant不清周期用量 |
| Issuer Licensing | feature目录、license版本、冻结批次、签发outbox/撤销 | 审批→签名→条件发布 | 私钥不入普通表；补偿用新revision |
| Audit | 行为及最小对象定位 | request/operation→审计 | 不存全聊天/token；普通业务不能改历史审计 |

## 必须统一的字段模式

跨JS的64位ID、bytes、单调seq和revision使用精确十进制字符串；DB采用明确范围和类型，不用浮点。业务时间、接收时间、索引时间分别命名，未知保留null/状态。

所有跨tenant外键按R07/R39构造复合约束；不能只在WHERE加tenant。分区表唯一性含分区键的约束与全局稳定身份服务同时设计，不能宣称一个局部分区索引解决全局去重。

人类用户名、微信来源external ID、客户商业licensee ID、产品tenant ID、设备ID、deployment ID不是同一主键。所有API和事件声明版本、owner、幂等身份、去敏策略和保留期限。

## 交付时填写的实际字典

对每张实际表登记：模块owner、建表migration、主键/唯一、FK含tenant、索引目的、RLS角色、热/冷数据体量、TTL/GC、重建办法、备份和删除影响、调用API、测试ID。无owner不合并，无迁移演练不发布。

本次只提供导航；已有表和migration不能根据本表名字批量重命名。与真实代码不一致时由单一owner写映射/ADR，不并行手改三份类型。
