# 二次开发指南

目的：新维护者不依赖AI会话即可扩展；规则R34/R40是唯一工程门槛。

## 扩展一：新增数据来源

先用合成fixture记录detect、schema探测、账号身份、shard generation、稳定ID、游标能力和不支持情况；实现既有SourceAdapter接口，而不是在UI里读库。新数据经历统一标准化、质量隔离、Outbox与receipt。游标 cursor.watermark 是单调 seq 十进制字符串，按回放推进（`packages/source-contract/source-adapter.json`）。

必须验证低位回填、重复观察、相同正文不同消息、64位ID、空正文媒体、旧schema和账号切换。若数据源没有完整变更序列，记录覆盖限制与全量对账策略，不冒称可靠CDC。

## 扩展二：新增业务MCP工具

先查现有ToolRegistry和ApplicationService，冻结input/output、scope、对象ACL、feature、风险、审批、幂等、字节/时间预算及测试ID。完成handler→service映射，再更新目录、Prompts/相关runtime Skill和文档。无数据权限时既不可发现敏感工具也不能直接调用成功。

禁止让新工具透传任意SQL/URL/path/command；所谓通用工具只能在有限已注册operation里选择，不能靠动态eval执行模型指令。

## 扩展三：新增收费功能

在唯一feature目录增加稳定key、依赖、兼容策略和操作映射；发行端、签名claims、客户决策和UI由同一合同生成/验证。旧全功能套餐不自动获得未来feature，依赖不自动赠送。

测试新grant默认待启用、到期/撤销、队列重试/回调、配额并发、升级兼容、已有数据取回。不要在各页面散落if套餐名，也不要重复实现另一套batch授权算法。

## 扩展四：新对象存储或媒体转换器

实现ObjectStore/派生处理端口；验证multipart、hash、Range、权限、到期和错误分类。转换在有限沙箱/slot内运行，不占用所有交互资源。结果只作为派生件，不改原件；格式支持及许可证进发布清单。

## 贡献闭环

工作项→合同与反例→最小实现→当前快照测试→风险复核→合并后回归→说明更新→交接。共享合同和migration进入串行窗口，多个分支不各自生成同名迁移。

验收演练：接手者修改一条心跳告警策略、加一个只读来源fixture或受限MCP工具，并能定位、测试、回滚/前向修复；不要求全项目重写，也不靠混淆隐藏逻辑。
