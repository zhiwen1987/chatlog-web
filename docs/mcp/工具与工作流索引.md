# MCP工具与工作流索引

工具清单自动从本包开发规则R15表格和R15.7显式工具名提取，文件为[mcp/tool-inventory.json](../../mcp/tool-inventory.json)。它记录必做工具的名称/域/来源，而不是实现或授权证明。每项当前为specified_not_implemented_by_this_bundle。

DSH实施时，将目录逐项补为真正ToolRegistry：准确input/output Schema、scope、feature/依赖、对象ACL、风险、注解、外发/费用、字节预算、幂等/expectedVersion、审批、job模式、服务方法和测试ID。只有完整合同并通过联调才允许注册。

## 工作流与工具组合

| 工作流 | 典型顺序 | 默认权限 |
|---|---|---|
| 客户证据复核 | system_me→customers_get→profile_get→profile_evidence_get→messages_context | 只读，用户范围＋外发 |
| 会话交接摘要 | conversations_get→conversations_messages→messages_context | 有限时间/数量，覆盖说明 |
| 同步故障诊断 | sources_health→devices_health→sync_account_status→sync_errors | ops只读，不能直接修cursor |
| 完整性解释 | integrity_report_get→media_integrity_get→search_coverage_get→backup_status | 只读、范围asOf |
| 客户合并 | customers_merge_preview→可信审批→customers_merge→审计/job | R4，强约束；不是默认业务Skill |
| 大导出 | messages_export→持久job→jobs_get→受控资源 | 导出scope、ACL/预算、短期资源 |

运行时Skills在[运行时Skills目录](../agent/Skills目录.md)，实际文件入口见[Skills目录](../agent/Skills目录.md)；它们只覆盖上表前四个只读流程。其它写流程必须直接由明确用户请求与真实审批驱动，不以skill名称预授权。

Prompts沿用规则R15中的10个标准工作流；名称和内部prompt版本分开。Skills/Prompts可以说明如何做，不能替代工具的服务端校验，也不能把每个工作流再实现一套业务引擎。

## 建议的最小接入过程

先只注册system_me/system_capabilities并测OAuth；再注册一组真实只读查询，最后按测试证据逐步打开写操作。所有未知schema、scope或feature映射保持未发布，不能用空schema、`any`或通配scope临时上线。
