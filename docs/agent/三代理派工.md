# 三代理派工与Agent角色

规范归口：[AGENTS A09](../../AGENTS.md)、[手册M08](../../开发手册.md#m08)。本目录是角色说明，不是DSH原生subagent配置，也不表示已创建运行实例。

| 角色文件 | 默认职责 | 同时执行限制 |
|---|---|---|
| [协调者](../../agents/协调者.md) | 基线、合同冻结、派工、只读复核、合并、证据与交接 | 不做第4个并行编码者；共享修改在串行窗口 |
| [A](../../agents/A-数据服务.md) | 数据服务/查询/同步服务端的一个明确工作项 | 1个槽位，一个write owner |
| [B](../../agents/B-桌面媒体.md) | Rust原生/本地Outbox/传输恢复或桌面指定界面 | 1个槽位，不与A共写合同 |
| [C](../../agents/C-界面联调.md) | 指定Vue界面、MCP适配或独立复核测试中的一项 | 1个槽位；复核也占槽，不能再派第4人 |

## 一波的正确流程

协调者验证宿主委派/取消/工作区隔离→冻结唯一合同/迁移owner→建立互不写冲突的3个工作项→分别传给A/B/C短上下文→观察真实run ID和日志→收集patch/结果→串行合并→当前集成快照回归→更新进度/交接。

不能把“后端”“客户端”“前端”整个大系统一次扔给三个代理。任何共享类型、配置、锁文件、认证根、签名根和migration变更都先归单人。文件路径不相交但共同改变一个协议，也属于冲突。

Worktree隔离代码不是安全沙箱。每个槽的数据库、对象前缀、端口、测试身份、预算和临时目录也要隔离；不共享生产凭证。子代理可调用现有授权工具做本项工作，但不能递归派生其他代理。

## 当前环境不支持时

只开验证过的实际数量，给出缺少哪项能力，继续无冲突串行任务。不要靠三个角色名伪装三个run，不猜`dsh --parallel 3`命令。官方资料只证明提供可选委派机制，用户本机仍要预检。[V03,V04]

## 交付合同

每项返回workItemId、slot、assignmentGeneration、base/head或patch hash、修改路径、合同摘要、实际测试、未完成/阻塞、风险和下一步。全局`.delivery/`只由协调者更新；子代理写自己的结果和日志。接续格式见[模板](../../templates/HANDOFF.md)。
