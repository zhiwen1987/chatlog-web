# 升级、回退、卸载与迁移

适用客户服务端、桌面与发行方；规则R20/R22/R33/R39为真源。本文要求正式发布时按真实artifact和migration补齐路径，不提供会自动操作生产的脚本。

## 升级前置清单

记录当前commit/版本、DB及claims/sync/presence/MCP版本、镜像digest、活跃设备、待ACK队列、运行jobs/批量发证状态、备份集合及恢复演练证据。确认新旧客户端协议兼容窗口、磁盘暂存空间、索引双版本空间和许可证版本范围。

先隔离预演，备份并实际验证可恢复；仅“备份作业成功”不足。评估迁移是否在线、锁级别/时长、索引创建方式和旧程序兼容。expand→回填→切读→contract分阶段；不能在滚动多副本同时跑迁移。

## 服务端升级流程

审批窗口→drain新任务领取→完成短事务/安全checkpoint→执行单一受控迁移→小流量新版本→冒烟与完整性/权限/水位检查→扩大流量→观察→确认。读写混版本必须事先证明安全。migration失败先停后续步骤，不强行标成功。

## 桌面升级流程

验更新签名→下载并验证→安全暂停原生核→记录Outbox/配置版本→迁移临时副本→原子切换→重连新设备会话并核receipt→恢复。更新不可开启未获本地同意的目录或外发。程序升级不清设备身份和商业部署绑定。

## 回退

先判断DB/local-state/schema是否仍兼容旧二进制。不兼容时走前向修复或隔离恢复后切换，不直接将旧镜像挂到新库。回退授权业务不倒退revision；已发证补偿是新审批新版本。

恢复需要处理最后备份之后已经耐久ACK的数据重放，以及最新删除/撤销账本。发现版本和账本未知时阻塞切回，不靠重建索引掩盖丢记录。

## 卸载和终止服务

停止新增采集→按业务权限取回数据→核验导出与备份→撤销设备/机器凭证和OAuth注册→单独确认数据清除范围。软件卸载默认不自动清除服务器、对象、备份和本地未ACK。客户密钥的保留/销毁需明确责任与证据。

不要执行未审批的`down -v`、删除bucket、清空`.delivery/`或整盘清理。删除要求如遇备份不可变/外发副本/离线设备，显示待完成范围和日期，不宣布全部即时消失。
