# 进源网络授权中心安装与上线

**仅发行方运维使用，不要求客户安装。** 授权中心独立域、身份、数据库、签名权限和备份；不是客户聊天服务端的“超级管理员页面”。规则R33/R42是业务真源。

## 准备物与隔离

从正式发行清单取得issuer-web、license-authority和必要迁移/健康入口，绑定可信域名/TLS。建立独立OIDC/管理角色：提出授权、批准、发布、撤销、密钥管理、审计；高风险操作者分离、MFA和恢复流程实测。

签发私钥位于KMS/HSM或受审查隔离签名器；发行API只能提交固定产品用途的claims，不准签任意payload。发证key、软件更新key、OS签名证书和客户数据key分别管理，开发/测试/生产信任根隔离。

密钥初始仪式与双人保管由授权人员操作，不交给DSH自动生成并打印生产私钥。本包没有开发万能license或关授权开关。

## 上线顺序

1. 验证发行包签名、镜像digest、迁移和备份恢复入口；建立独立卷与最小DB角色。
2. 由单一迁移作业建issuer库；配置签名器白名单和最小权限；验签信任集版本固定。
3. 创建不同人员的管理员与审核身份，验证客户域Cookie/token在issuer域无效。
4. 导入经过审批的产品feature目录；依赖关系无环，目录版本固定，不启用通配符。
5. 用隔离测试产品/部署完成单项签发、续期、撤销、过期和错误签名测试。
6. 完成3个测试license的批量预览/批准/执行；故意让1项版本冲突，确认不会覆盖且计数真实。
7. 重复execute和worker故障恢复，确认续期after值不反复加天、单项不重复发布。
8. 测试客户离线/再上线、published与applied_reported区分、签名器故障不拖死续租。
9. 备份issuer库、撤销/信任集与签名器恢复资料；演练后才开放真实发证。

## 客户激活所需的发行信息

产品ID、可信issuer地址、公钥信任集的受信分发方式、激活入口、已审批合同与部署配额。不要让客户上传聊天/微信明文ID/附件hash清单作license验证；最小遥测按R33。

## 批量授权操作

客户筛选→明确冻结license列表→功能/动作/期限/配额→逐项before/after→审批摘要→异步执行→按项结果→客户应用。单批上限、窗期、并发和停止策略只引用规则R42，不在这里另写一套默认值。

整张license关联多个部署时，预览必须展示全部影响；已发布项不能用取消假装回滚，补偿需新审批新revision。签名库只保存授权资料，客户tenant数据库不能进入issuer备份。

## 灾备与密钥事件

恢复后revision、activation epoch、lease seq和撤销账本不能倒退；旧签名key泄漏应轮换、按信任策略撤销和通知，不远程删客户数据。离线租约不能承诺即时撤销；root/源码修改残余风险明确披露。

交接使用[安全与密钥交接](../handoff/安全与密钥交接.md)。任何实际发证、撤销、生产迁移仍需要发行方审批，文档不是授权凭据。
