# 客户服务端安装与首次验收

归属：规则R02/R04/R14/R20/R22/R29/R33/R42。下列为发布时必须实现并验证的SOP；本包不含应用镜像、Compose或迁移程序，不可把命令模板当作已提供的软件。

## 1. 准备安装记录

复制[部署记录](../../templates/DEPLOYMENT_RECORD.yaml)到受限运维空间，填入实际主机OS/架构、发行版本、镜像digest、域名、证书状态、卷挂载、外部IdP和对象后端。只存秘密的引用位置，不写值。

选择core、large-text或已实测ha档。core包含业务服务/Worker、PG、对象后端及身份接入；large-text增加检索服务并隔离I/O。硬件以规则R23与样本容量测量为依据，1TiB档案不等于只需要1TiB盘。PG数据目录不能随意放网络共享；持久卷不能留在容器可写层。

## 2. 网络与身份

对外只暴露网关HTTPS及明确必要入口；PG、对象管理、Worker、调试端口不对公网裸开放。桌面主动连服务端，不要求从公网入站到员工电脑。时间同步、DNS、证书链、代理超时、上传大小和Range读取都须检查。

配置OIDC issuer、精确redirect URI、resource audience、client类型和可信origin；不得`*`全开放。创建首个管理员使用一次性bootstrap流程，禁用默认密码。MFA与恢复代码单独受限保管，验证应急登录不会绕过数据权限。

## 3. 存储、配额与备份

PG、对象、暂存上传、检索、日志与独立备份分别挂卷并设置空间阈值。S3后端验证multipart、真实checksum语义、Range、版本及权限；不把ETag当通用全文件SHA-256。供应商兼容性必须实测。

在第一份真实数据进入前配置至少一个独立故障域备份和恢复权限，登记密钥版本。业务凭证不能同时删除主数据和所有备份。未完成备份配置的环境显示未保护状态。

## 4. 配置与启动（模板有前置条件）

从**真实发行manifest**取得Compose文件、环境文件和项目名；不要猜文件名和service名。先验证签名与镜像digest，再本地查看脱敏配置。若清单缺任何必要入口，停止上线并回到DSH补交付，不改成随意运行镜像。

```bash
# Bash模板：这三个变量由管理员按实际发行清单赋值，本包没有这些产品文件
: "${WCM_COMPOSE_FILE:?必须来自真实发行清单}"
: "${WCM_ENV_FILE:?必须来自真实部署记录}"
: "${WCM_PROJECT:?必须是已确认独立项目名}"
test -f "$WCM_COMPOSE_FILE" && test -f "$WCM_ENV_FILE" || exit 1
docker compose --env-file "$WCM_ENV_FILE" -p "$WCM_PROJECT" -f "$WCM_COMPOSE_FILE" config --quiet
# 再按发行说明完成数据库初始化/迁移，随后启动；禁止由所有副本同时自动迁移
docker compose --env-file "$WCM_ENV_FILE" -p "$WCM_PROJECT" -f "$WCM_COMPOSE_FILE" up -d
docker compose --env-file "$WCM_ENV_FILE" -p "$WCM_PROJECT" -f "$WCM_COMPOSE_FILE" ps
```

命令只在Docker/Compose已经按目标OS安装并验收、变量已填、迁移已完成时适用。`config --quiet`避免把展开秘密打印到日志。上面没有替你完成TLS、发证、数据迁移或备份。Compose单机不等于HA。[V08]

## 5. 商业许可与功能启用

管理员在可信客户域激活已购买服务端许可；签名验证成功后检查平台grant、期限、配额和部署绑定。平台私钥不下发，客户不能自发证。

逐功能启用所需能力；新授予功能默认不自动运行。外部AI/OCR/ASR需要另行配置提供商、外发同意和预算。先测试授权中心短暂断网不会阻塞每次查询，更不能锁历史数据。

## 6. 首次验收顺序

1. 先只用合成数据：合法登录成功，另一租户/越权对象访问拒绝。
2. 配对一台设备，观察online与源状态分开；暂停同步仍能在线。
3. 同步少量文字与四类媒体；接收/发布/校验/索引分开显示。
4. 断开上传网络、恢复并重试；最终记录和hash一致，无重复账目。
5. 验证关键词、上下文与基本导出结果；异常格式能报真实原因。
6. 验证MCP未认证拒绝、只读scope不能写、Host不支持Tasks时能查询job。
7. 执行隔离恢复演练并比对消息、对象、密钥及删除抑制；再接入真实数据。

每步保存版本、时间、环境和证据，不把容器显示running当作安装成功。生产前还需完整发布门禁。

## 7. 安装失败与安全退出

先留脱敏日志，判断TLS/IdP/PG/对象/迁移/许可哪一层失败；暂停新采集，保留已确认数据。不能`docker compose down -v`删卷重来。迁移不兼容时遵循已审查前向修复/隔离恢复方案，不能只换旧镜像。
