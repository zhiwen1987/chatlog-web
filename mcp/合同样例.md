# MCP应用层合同样例

本目录input/output JSON Schema和fixture仅示范`messages_context`的结构化参数/结果。不是完整MCP HTTP报文、SDK实现、真实数据库结果或可直接发布的全部ToolRegistry；产品合同的唯一落地位置是实际仓库`packages/contracts/`。

input只接受messageId/before/after，不接受tenantId/userId/任意SQL。默认前后20条；服务端还必须做语义校验：before+after≤200，目标中心消息存在且在ACL内，总响应受256KiB预算。JSON Schema单独不能证明这些跨字段、权限和字节约束。

output给出消息revision、原时间可null、内容可null、contentTruncated和decodeStatus。coverage.complete只表示本次已授权已发布上下文，不代表微信全历史完整或附件都备份。长正文只保留有限片段和可续读资源，不能默默截断。

本样例使用fixture-message-001，所有数据合成，asOf只是样例。产品实际的ID/版本范围、cursor绑定、错误码及结构化结果封装要与既有合同审核后合并，不能据此重写已有稳定wire合同。

MCP结果同时按固定SDK提供structuredContent与兼容短text；工具业务失败需正确isError，HTTP鉴权和协议错误用相应通道，不用200“成功文本”掩盖拒绝。所有外部$ref不在运行时任意下载。
